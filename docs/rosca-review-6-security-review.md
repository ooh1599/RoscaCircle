# ทบทวน On-chain ROSCA + Microfinance บน Arc (ส่วนที่ 6: ตรวจหาช่องโหว่และแก้ไข)

วันที่: 22 พ.ย. 2026 ป้ายกำกับ [F] ข้อเท็จจริง [A] สมมติฐาน [P] ข้อเสนอ

## 0. ขอบเขตและข้อจำกัด

- **ยังไม่มีโค้ดสัญญา** รอบนี้ตรวจ "แบบ" (กติกาและสเปกในส่วนที่ 1 ถึง 5) แบบฝ่ายโจมตี ไม่ใช่การตรวจโค้ด เมื่อเขียนสัญญาแล้วต้องตรวจซ้ำกับโค้ดจริงและให้ผู้ตรวจอิสระทำอีกชั้น
- การตรวจนี้หาไม่ครบ ช่องโหว่ที่ไม่พบไม่ได้แปลว่าไม่มี
- ข้อเท็จจริงที่ตรวจกับ Arc Testnet วันนี้: USDC `0x3600…0000` มี 6 ทศนิยม, มี `isBlacklisted(address)`, มี `authorizationState(address,bytes32)` (สอดคล้อง EIP-3009) [F]
- ทุกข้อแก้ด้านล่างถูกรวมเป็น "สเปกที่แก้แล้ว" ที่ยึดแทนข้อความเดิมถ้าขัดกัน และมีการแก้ไขในไฟล์ส่วนที่ 3 และ 5 ในจุดที่ขัดโดยตรง

## 2. ช่องโหว่ระดับวิกฤต

### V1: ผู้สร้างกลุ่มเติม Sybil เข้ากลุ่มหลังที่คนอื่นยอมรับแล้ว
- **โจมตี**: สมาชิกจริงสมัครเพราะเห็นเพื่อน ผู้สร้างเติมกระเป๋าตนเองในที่ว่างที่เหลือ (โดยเฉพาะคิวต้น) แล้วหนีด้วยก้อนต้นรอบ หรือสลับตำแหน่ง/เปลี่ยนค่า C หลังมีคนวางเงินแล้ว
- **ผล**: ความเสียหายเท่าส่วนไม่มีหลักประกันของคิวต้นทุกคิวที่ผู้โจมตีถือ
- **แก้**: การยอมรับของสมาชิกต้องผูกกับ `termsHash` = แฮชของ (ที่อยู่ factory, codehash ของโค้ดกลุ่ม, N, C, φ, D, ρ, G, วันเริ่ม, **รายชื่อที่อยู่สมาชิกทั้งหมดพร้อมคิว**) เซ็นแบบ EIP-712 ทุกคน กลุ่มล็อกได้เมื่อมีลายเซ็นครบ N และตรงกับแฮชเดียวกัน ถ้ามีการเปลี่ยนรายชื่อหรือพารามิเตอร์ แฮชเปลี่ยน ลายเซ็นเก่าใช้ไม่ได้ ก่อน Locked สมาชิกถอนเงินได้เองทุกเมื่อ ไม่ต้องรอผู้สร้าง
- **ทดสอบ**: ผู้สร้างพยายามเปลี่ยนรายชื่อ/ค่า C หลังมีลายเซ็น ต้อง revert; ลายเซ็นของ termsHash เก่าต้องล็อกกลุ่มไม่ได้

### V2: ฟอกหนี้ด้วยการเปลี่ยนตัวสมาชิกหลังรับก้อน
- **โจมตี**: คิว 1 รับก้อนแล้วเสนอ "ผู้แทน" เป็นกระเป๋าใหม่ที่วาง D ใหม่ ผู้ออกได้ D เดิมคืน ทิ้งหนี้ให้กระเป๋าที่ไม่มีมูลค่า (หลักประกันในสัญญาลดลงเท่า D)
- **แก้**: **ไม่อนุญาตผู้แทนหลังรับก้อนแล้ว** ผู้ที่รับก้อนแล้วออกได้เฉพาะด้วยการชำระภาระที่เหลือครบ (แล้วรับ holdback และมัดจำคืน) ผู้แทนก่อนรับก้อนทำได้ แต่การสลับมัดจำต้อง atomic: ผู้แทนวาง D ใหม่ในธุรกรรมเดียวกับที่ D เดิมถูกคืน ยอดหลักประกันรวมไม่ลดลงแม้แต่ช่วงเดียว และผู้ออกไม่ได้รับเงินที่จ่ายเข้ากองกลางไปแล้วคืนจากสัญญา
- **ทดสอบ**: invariant ยอดหลักประกันรวมของกลุ่มไม่ลดลงจากการสลับสมาชิก; ผู้รับก้อนแล้วเรียกผู้แทนต้อง revert

### V3: ปิดกลุ่มแบบเร่งรัดหนี้ทำร้ายลูกหนี้ที่ซื่อสัตย์
- **จุดอ่อนของข้อความเดิม**: ส่วนที่ 3 หัวข้อ 2.3 ให้ wind-down หักกลบ "ลูกหนี้สุทธิที่ไม่ผิดนัดจ่ายส่วนต่าง" ทันที ผู้รับก้อนต้นรอบที่ซื่อสัตย์แต่ยังไม่มีเงินก้อนใหญ่ ถูกทำให้ผิดนัดเพราะการปิดของคนอื่น หรือผู้โจมตีตั้งใจทำผิดนัดสองรายเพื่อกระตุ้นการปิดกลุ่มบังคับลูกหนี้ซื่อสัตย์
- **แก้**: wind-down **ไม่เร่งรัดหนี้** ลูกหนี้ที่ไม่ผิดนัดชำระงวดตามตารางเดิม เงินที่ชำระหลังประกาศ wind-down ถูกจัดสรรให้เจ้าหนี้สุทธิตามลำดับน้ำตกหัวข้อ 5 ผู้ที่ชำระครบ ได้ holdback และมัดจำคืน เกณฑ์เข้า wind-down ไม่เปลี่ยนสิทธิของผู้ที่ไม่ผิดนัด
- **ทดสอบ**: ลูกหนี้ซื่อสัตย์ที่จ่ายตรงเวลาไม่เคยถูกประกาศผิดนัดเพราะ wind-down

### V4: ใช้มัดจำจ่ายงวดแล้วปล่อย holdback ทำให้หลักประกันหาย
- **โจมตี**: ในหัวข้อ 3 ส่วนที่ 5 holdback คืนทุกงวดที่ "จ่ายครบ" ถ้างวดครบด้วยมัดจำ (กลไกขาดสภาพคล่องชั่วคราว) แล้ว holdback ถูกปล่อย สมาชิกได้เงินคืนโดยไม่ได้จ่ายเอง แล้วหนี หลักประกันหมดทั้งสองถัง
- **แก้**: holdback คืนเฉพาะเมื่อ (ก) งวดนั้นจ่ายจากกระเป๋าสมาชิกเอง (หรือผู้อื่นจ่ายแทนเงินจริงเข้ามา) ไม่ใช่จากมัดจำ และ (ข) มัดจำเต็ม D ณ ขณะนั้น ถ้ามัดจำพร่อง การคืน holdback ถูกพักจนกว่าจะเติมเต็ม
- **ทดสอบ**: งวดที่จ่ายด้วยมัดจำต้องไม่ปล่อย holdback; มัดจำพร่องต้องพักการคืน

### V5: ผู้ดูแลถูกตั้งเป็นผู้ deploy และเทมเพลตเปลี่ยนมือ
- **ความเสี่ยง (ก)**: ถ้า `deploy_contract` ของแพลตฟอร์มใช้กระเป๋า deployer ร่วม แล้วตั้งผู้ดูแลเป็น `msg.sender` ผู้ดูแลจะเป็นกระเป๋าร่วมที่ไม่ใช่ของเจ้าของโครงการ **แก้**: `admin` เป็นพารามิเตอร์ constructor ชัดเจน ห้ามใช้ `msg.sender` ใช้ที่อยู่ `0x223c2D5Af8120cAb3c68b5587feC7c8649Ce9c15` และตรวจหลัง deploy ด้วยการอ่าน `admin()`
- **ความเสี่ยง (ข)**: กลุ่มสร้างด้วย minimal proxy (clone) ถ้า implementation ถูก `initialize` โดยคนอื่นหรือมี `selfdestruct`/`delegatecall` โค้ดต้นแบบอาจถูกทำลายหรือยึด **แก้**: implementation ล็อก initializer ตั้งแต่ constructor, ไม่มี `selfdestruct` และ `delegatecall`, factory เรียก `initialize` ในธุรกรรมเดียวกับการสร้าง clone, ผู้ใช้ตรวจ codehash ก่อนเซ็น (V1)
- **ความเสี่ยง (ค)**: ผู้ดูแลเปลี่ยน implementation ที่ factory ใช้ ชี้กลุ่มใหม่ไปโค้ดอันตราย **แก้**: implementation เป็น `immutable` ใน factory ไม่มีฟังก์ชันเปลี่ยน เวอร์ชันใหม่ = factory ตัวใหม่ (ตรงกับส่วนที่ 3 หัวข้อ 7.5)

## 5. สเปกที่แก้แล้ว: ลำดับน้ำตกและกติกาหลักฉบับใหม่

ใช้แทนข้อความเดิมถ้าขัดกัน

1. **งวด** = C + ρ ครบเมื่อได้ครบทั้งสองส่วนจากการจ่ายจริง (ρ ก่อน)
2. **เส้นเวลา**: ครบกำหนด T (คำนวณจากเวลาเริ่มกลุ่ม + ลำดับรอบ ไม่ใช่จากเวลาที่จ่ายก้อน) → ช่วงผ่อนผัน G ไม่มีค่าปรับ → หน้าต่างแก้ตัว 24 ชม. มีค่าปรับ → ประกาศผิดนัดได้
3. **ใช้มัดจำชั่วคราว** (ขาดสภาพคล่อง) เกิดเมื่อพ้นหน้าต่างแก้ตัว ไม่ใช่ตอนพ้น G (ลดโอกาสใช้มัดจำโดยไม่จำเป็น) งวดที่จ่ายด้วยมัดจำ **ไม่ปล่อย holdback** และ holdback พักจนมัดจำกลับเต็ม D
4. **ลำดับน้ำตกเมื่อประกาศผิดนัด** (ยึดไม่เกินภาระที่ยังไม่จ่าย + ค่าประกาศ ส่วนเกินคืนผู้ผิดนัด ดูส่วนที่ 10 X1): (1) holdback ของผู้ผิดนัด (2) มัดจำคงเหลือ (2b) ยอดที่ผู้ค้ำล็อกไว้ ถ้ามี (3) กองทุนสำรอง ไม่เกินเพดานต่อเหตุการณ์ (4) ความสูญเสียถาวรหารให้เจ้าหนี้สุทธิ ปัดเศษตาม V20
5. **หลังประกาศผิดนัด** ผู้ผิดนัดยังชำระหนี้ได้เต็มจำนวนคงค้าง เงินที่เข้ามาถูกจัดสรรคืนให้ผู้ที่ได้รับความเสียหายตามสัดส่วน และไม่คืนสถานะประวัติ
6. **ผู้แทน**: ก่อนรับก้อนเท่านั้น สลับมัดจำแบบ atomic; หลังรับก้อนไม่มี
7. **สละคิวก่อนถึงตา**: ข้ามรอบของคิวนั้น คืนเงินรอบที่เก็บแล้ว
8. **wind-down**: ไม่เร่งรัดหนี้ ลูกหนี้ซื่อสัตย์ชำระตามตารางเดิม
9. **ผู้เรียกระบบ**: ค่าตอบแทนมาจากค่าปรับของผู้ล่าช้าเท่านั้น
10. **การย้ายกระเป๋า**: คงสถานะและหนี้ ไม่ทำในหน้าต่างแก้ตัว/หลังผิดนัด

### Invariants เพิ่มเติม (ต่อจากข้อ 1–8 ส่วนที่ 3 หัวข้อ 6.3)

9. ยอดหลักประกันรวมของกลุ่ม (holdback + มัดจำ + ยอดผู้ค้ำ) ไม่ลดลงจากการเปลี่ยนสมาชิกหรือการย้ายกระเป๋า
10. holdback ของสมาชิก = φ × ภาระที่ยังไม่จ่าย ณ ทุกสถานะ และการคืนเกิดเมื่อจ่ายจริงเท่านั้นพร้อมมัดจำเต็ม
11. ผลรวมทุกถัง (งวดรอบปัจจุบัน + holdback + มัดจำ + กองทุน + ยอดเบิกได้) ไม่เกินยอดที่รับเข้าจริงตลอดกลุ่ม ไม่มีเงินเกิดเองหรือหายเอง รวมกรณีปัดเศษ
12. `declareDefault` สำเร็จได้ต่อเมื่อสถานะการชำระในบล็อกนั้นยังค้างอยู่และพ้นหน้าต่างแก้ตัวแล้ว
13. ผู้ค้ำที่ถูกใช้ยอดล็อกต้องเป็นยอดที่เกี่ยวกับผู้ถูกค้ำที่ผิดนัดจริง ไม่ใช้ข้ามผู้อื่น
14. ค่าตอบแทนผู้เรียกรวมต่อหนึ่งสมาชิกต่อหนึ่งรอบ ไม่เกินค่าปรับที่ผู้นั้นจ่ายจริง
